## Why we kept looping (the diagnosis)

1. **No single written photo chain.** Spec §5.1 has three unreconciled layers, and code comments, STATUS and the
   handoff each describe a different chain. Each fix was built against whichever version was read.
2. **One failure, one new source.** When photos came up short, a source was added (official images, then (c)),
   each with its own checks and exceptions. (c) went to code without a proposal, and its scope grew mid-build.
3. **Links disagree with each other.** The Writer's `photo_available` means "has a P18 photo", but the finder kept
   gaining sources the Writer can't request. One vision prompt is shared by three links, so editing it for one
   changed the frozen stock link.
4. **A decision was recorded that Tommy never made.** `official.ts` says Google and Microsoft rows were approved by
   Tommy. They weren't.

## Decisions (Tommy, 2026-10-07)

- **The photo system is fully automatic and uses only sources with no rights questions.** No human picks photos,
  no per-company approvals. When nothing is found, the slide is a designed slide; we don't add another source.
- **Logos:** "If there are free, open-to-use logos that are just preferred not to be used by the companies, we can
  definitely use them." A logo card is allowed for any identity-verified organization whose Commons logo file
  passes the existing licence check. Brand-guideline preferences don't block it.
- **Official company images (a): off.** **(c) Commons/Openverse more-photos: dropped.** (d) charts and (e) post
  screenshots: not planned.
- **Lucas is out of the workflow.** Tommy alone signs off. Helios-designed graphics are made by Claude Code from the
  Helios design system and approved once by Tommy.
